## Efficiency and change control

- Use deterministic processing for parsing, counts, hashes, IDs, transforms and permission checks; call the model only where interpretation/adaptation is needed.
- Reuse source manifests, downloaded artifacts, prior code decisions, cache and successful stage checkpoints. One writer per file; no broad shared-tree staging or destructive cleanup.
- Choose bounded targeted tests after a concrete change. Run broad integration checks when justified by integration, not on every progress update. Keep logs/artifacts, not entire histories in prompts.
- Parallelize only independent tasks with compact briefs. Prefer one integration owner and brief result reports. Existing named subagents are not assumed still running.
- A replacement architecture needs a small proof plus comparison of remaining implementation, migration, dependencies, operating cost and rollback. Measure savings; do not claim a multiplier.
- Existing Cloudflare usage has no numeric owner cap, but each experiment needs a purpose and a stop condition. No repeated paid run of the same unexplained failure.
- Any unsupported external capability is a named blocker, not permission to silently switch models, reintroduce training or cut a required feature.
