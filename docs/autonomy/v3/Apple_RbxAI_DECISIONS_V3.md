## Implementation defaults, not additional owner answers

1. Use a noninteractive current-version badge, not a new selector containing only one choice. Choose the numeric release version from the actual release baseline; V3 does not assign it.
2. A finite versioned release-library manifest resolves “complete library” without claiming complete coverage of the entire internet. All existing owner inputs must be accounted for.
3. Serve production catalog/artifacts independently of the owner's Mac; build in customer Studio. This implements the commercial self-service destination and connection requirement.
4. Prefer image compositing from the real game and prepared assets for Generate Branding, so no unapproved generative model is silently introduced. The window must return actual images, not only prompts.
5. Default theme selection can be studded; the user can choose the three approved UI options. Store it per project/request without modifying the world specialty.
6. Component demonstrations are not production behavior. All displayed actions/counts/files/citations must come from actual authorized project data. No synthetic activity feed.
7. Keep implementation integration tests focused and release proof end-to-end. Do not restore the old review bureaucracy simply because a script references it, or remove necessary tests to conceal a defect.
8. Critical security checks remain deterministic. Jev outputs are probabilistic advice and never authority to access, mutate, charge or mark success.
