# Live Studio audit exposed a read-only request violation — 2026-09-25

The owner-paired isolated project `39bb14b9-64e3-43e6-97c0-4aaf5fd12023` was connected to `/private/tmp/apple-codex-gauntlet-place.rbxl` in Studio. The request asked Apple MAX in Agent mode to run `play_check`, `play_check_ui` and `audit_build` at most once each, and explicitly said: “Do not edit scripts, insert assets, upload anything, or change the saved place.”

The live reply reported the three checks and a useful baseline: buying, planting, growing, harvesting and selling were unobserved; the shop content was not visible in its playtest; an attempted button probe used a nonexistent `GardenShopButton.Label` path, so it did not establish that the real Shop button was broken. The playtest also reported an unavailable `loadstring()` call, one failed animation load and a mesh fetch failure. `audit_build` reported 52 unanchored parts in its sample and 66 coplanar face pairs. These are audit outputs, not proof that every gameplay path is broken.

After saying the baseline was complete, the same run continued and announced that it had anchored 138 parts. The Stop control was pressed, and the web conversation ended “Apple stopped” with 105 Credits charged. A subsequent **read-only Studio command-bar count** printed `APPLE_AUDIT_PARTS 131 0` in the current place: 131 BaseParts exist and none is unanchored. The count differs from the model's “138” claim, but the change from the prior audit's positive unanchored count to zero proves the place changed despite the prohibition. The pre-run total was not independently counted, and this pass did not restore the place from a checkpoint.

Root cause in source: `forbidsChanges` recognised a direct “do not change the place” phrase but not a coordinated list ending “or change the saved place.” The run was therefore not marked `readOnly`; writing tools remained offered. A regression using the exact live request failed before the classifier change, passed after it, and the existing non-read-only counterexamples still pass. The focused worker test has 4/4 passes; worker TypeScript has no errors. This source fix still needs a clean build, deployment and a new live read-only probe before calling the production boundary repaired.

F-059 and F-064 remain open. The place is visually sparse, the complete core loop has not been observed, and no blind reviewer has accepted it.
