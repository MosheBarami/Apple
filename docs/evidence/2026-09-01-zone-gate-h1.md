# H1 — the zone gate nobody drew

**Date:** 2026-09-01 · **Place:** Golem Visual Benchmark (`116648235878426`) · **Studio playtest**

## The finding

The independent engineering critic, H1:

> The per-player zone gate is published by the server (`zone_<id>` attribute) and **read by
> nobody**. A player who pays 2,500 coins sees the gate unchanged; one who has not pays
> walks through and collects nothing with **zero feedback**.

Confirmed by search before touching anything:

```
$ grep -rn "zone_\|GetAttribute" src/ | grep zone_
src/server/Zones.luau:18:   a `zone_<id>` attribute, and the client reads that attribute to draw its own
src/server/Zones.luau:57:   local ATTR_PREFIX = "zone_"
src/server/Zones.luau:77:   player:SetAttribute(attributeName(zone.Id), Zones.isUnlocked(player, zone.Id))

$ grep -rn "GateOpen" . | grep -v Palette.luau
(no output)
```

The server published. Nothing consumed. `Palette.Pads.GateOpen` was defined for this and had
zero consumers — the client half was designed and never written.

## What was NOT wrong

The security model. `Zones.luau`'s header argues that per-player collision is unsound
(server `CanCollide` is global; a client-owned barrier lives on the machine of the person it
stops), so collision is decoration and `Collect` is enforcement. That is correct and is
unchanged. `tests/zones.spec.luau` now pins it with 13 tests, including the two that matter
most: a failed profile load is never ownership, and ownership must be exactly `true` rather
than merely truthy.

## The fix, in two halves

1. **`src/client/Gates.luau`** — reads `zone_<id>`, paints this client's view of the gate.
2. **`Collect.notifyZoneLocked`** — a throttled notice when a player stands in a zone they
   do not own, in the same shape as the existing `notifyPackFull` beside it.

## Measurements

All numbers below are from a running playtest, read out of the client DataModel.

### The gate renders the published state

| state | mean colour (13 parts) | mean transparency |
|---|---|---|
| before the fix | 232,62,62 (server's paint) | **0.012** — the authored value, untouched |
| locked, after | 232,62,62 (`Palette.Pads.Gate`) | **0.350** |
| unlocked, after | 70,200,85 (`Palette.Pads.GateOpen`) | **0.880** |

The unlocked reading was produced by the **server** publishing `zone_frost = true`, so the
replication path is included, not simulated.

### The transition is a real fade, not a jump

Sampled on `RenderStepped` inside a single call, so no round-trip latency hides the frames:

```
t=-1.000  T=0.350   (locked, settled)
t=+0.034  T=0.494
t=+0.100  T=0.616
t=+0.168  T=0.717
t=+0.236  T=0.793
t=+0.301  T=0.845
t=+0.369  T=0.874
t=+0.635  T=0.880   (settled)
```

Eight distinct values, decelerating — `Theme.motion` is wired, which also means the fade
collapses to an instant set for a player with reduced motion enabled.

### The locked notice fires where it should and nowhere else

| the player stands | zone | locked notices | over |
|---|---|---|---|
| `0, 3, -120` | Frost Hollow, **not owned** | **2**, exactly 8.0s apart | 10s |
| `-6, 4, -39` | between zones | **0** | 12s |
| `0, 3, 130` | Sunny Meadow, **owned** | **0** | 11s |

8.0s apart is `LOCKED_NOTIFY_COOLDOWN`. Text: `FROST HOLLOW IS LOCKED — 2,500 COINS`.

The owned-zone row is the control that matters: during those 11 seconds the same remote
delivered four `PACK FULL — SELL AT THE GOLD PAD` notices, so the zero is the gate working,
not a dead pipe.

## What the playtest caught that the tests could not

The first version of `Gates.luau` cached `gate:GetDescendants()` at init and painted that
list. In the playtest it produced **transparency 0.012** — the untouched authored value —
while emitting no warning and throwing no error. At client boot the gate Model exists before
its 13 children have replicated, so the cached list was empty and every paint was a loop over
nothing.

That is the same failure as H1 itself: code that runs and affects nothing. It is recorded as
F-29. Nothing short of running it in Studio would have found it — an empty list is
indistinguishable from success in every assertion that does not look at the pixels.

## Left standing

The toast is clipped by the Roblox topbar: `GuiService:GetGuiInset()` reports `0,58` and the
notice rendered as `FROST HOLLOW — 2,500` with `IS LOCKED` cut off above the viewport. That is
**M6**, still open, and this is a second surface affected by it — the modal was fixed earlier
this session, the wallet column and now the notification layer were not.

## Reproducing

```bash
cd apps/benchmark/crystal-canyon && python3 -m http.server 8777 --bind 127.0.0.1
```

Run `world/Install.luau` in Studio's Edit mode, press Play, then drive the states from the
client command bar with `player:SetAttribute("zone_frost", true|false)` and read
`workspace.Canyon.Gates.frost` descendants' `Transparency` and `Color`.
