Every picture below came out of the deployed product. The model was handed the construction library the product ships — what a shop is made of, how a tycoon plot reads — and asked to build the thing. What it wrote was then compiled and executed, and these are the shapes that came out.

What these pictures are, exactly

  • The model is the live one. Every screen is an HTTP call to the deployed Worker at apple.moshe-barami111.workers.dev. No local model, no cached answer.
  • The library is the product's own. The exact payload get_ui_construction and get_genre_kit return was put in the prompt. The model was given its library — on this endpoint it cannot ask for it, so nothing here shows that it would have chosen to.
  • These are not Studio screenshots. The model's Luau was executed and its instance tree resolved to real rectangles. Fonts, text wrapping and safe-area insets are not modelled, so treat this as an accurate plan rather than a photograph.
  • No artwork was invented. Where the model pointed at an image asset, the box is hatched and prints the id. Nothing was downloaded and nothing was uploaded to any Roblox account.
  • The failures are here too, at the same size as the successes, with the reason each one gives.
  • The code is here too. Every card opens the actual Luau the model wrote, numbered by line. Where a script did not compile, the line the compiler named is marked in it.
  • This is one attempt each, with no second try. The endpoint these ran through wires no tools, so a model that got something wrong had no way to be told. In the product it is told: a script is parsed before it is written, and one that does not parse is refused back to the model with the line and column rather than saved into your game. What that refusal leads to is not measured here — only that nothing broken is written.

What the library actually is

  • It is real, and the model can ask for it. 16 kinds of screen and 13 genres, distilled from 384 cited sources, served by two tools the model calls by name: get_ui_construction and get_genre_kit. 21 of 22 screens above were built out of it.
  • It holds no files. No images, no meshes, no asset ids — the corpus says so itself: “Project-authored construction observations distilled from shipped Roblox UI. No image, asset or third-party source is reproduced here.” It holds how a screen is put together, and the model writes the Luau. That is what every picture on this page is.
  • There is no store of ready-made assets, and there will not be one. The catalogue that tried held 511,208 rows and 0 of them could be inserted on the day it was measured. Every way of turning a file into a usable Roblox asset ends in an upload to a real account, Roblox will not archive an Image or a Decal, so every one of them would be permanent in your account — and some of those rows were other companies’ characters under a single licence claim. You deleted it on 20 September. It stays deleted.
  • What that costs you: nothing on this page. A screen built from construction notes is a screen that compiles, runs and belongs to you. What it cannot do is hand you someone else’s finished artwork.
