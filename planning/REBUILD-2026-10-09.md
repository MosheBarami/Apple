## Milestone 1 — stop the waste loops seen in the admin-panel run (2026-10-09, 57 steps, 16 min)

- `edit_script` returns a `bugs` list (unknown/implicit globals, infinite loops, unreachable code) in full and first;
  the `extended`/`expanded` typo had been cut off behind three style notes and cost ~8 steps of guessing.
- Contrast: outlined text (stroke ≥1.5 px, 4.5:1 from the fill) is no longer a `low_contrast` defect — server-side for
  build_ui now, and in the plugin's checker (takes effect when the plugin is updated).
- build_ui `rotation` (the agent's vertical "More..." tab failed on an unknown field).
- Agent tools: −run_luau, −apply_surface (set_properties TopSurface does it), +spatial_query, +scatter_instances (21 + 4 = 25).
- UI rules: anything closable has a visible reopen control; admin panels allow the place owner and Studio play-tests by
  default; small fixes are set_properties, not whole rebuilds.

## Phase B, part 1 — accounting and honest endings (2026-10-09)

- Shared budget settles each step with its cached input, against the model each hold was reserved for.
- Every turn records a terminal reason (`lastTerminal` in the admin export) and, unless it simply finished, shows the
  person a note: step limit, output limit, filter, provider error, incomplete, or **open UI defects**.
- Second admin-panel run (29 steps): the agent hid two overflowing sections with ClipsDescendants, never re-checked,
  then invented a user message ("just testing capabilities") and stopped. The phrase is in no stored message; it is
  the model's. Now: overflow defects carry `overflowFix` (scroll or smaller, clipping is not a fix); the prompt
  requires a re-check after a fix and forbids acting on words the person did not write; an unmeasured "finish" with
  defects open ends as `open_defects` with a note. Skins are generated plain (no ornaments; slicing smeared them);
  studded requests need a tiled stud texture.

## Phase B, part 2 — stop reaches Studio; late answers are reconciled (2026-10-09)

Mapped first (current code): op ids `op_<seq>_<time>`, at-most-once delivery, plugin-side replay window by op id, plugin
token supersede (an old poller gets 401), no scene revision, no Allow Edits gate in the backend (connecting is the
permission; writes need an approved account), pairing codes only on the old `/api/studio/claim` route.
- The agent tags every op of a turn (`turnId`); pressing stop calls `StudioGate.cancelTurn`, which discards that turn's
  queued ops (their waiters answer `transport`: provably never applied). The turn ends as `cancelled` with the count.
- A result that arrives after its op timed out is written to the oplog row (`late_ok`, `late_summary`, `late_at`) and
  told to the agent on its next tool call ("do not redo them blindly, read the place first"). Before, it was dropped.
- Not done: a scene revision counter from the plugin (needs a plugin release); manual edits are still only caught by
  per-script `base_hash`.

## Phase C, part 1 — the model sees its work (2026-10-09)

- `render_view` is on the agent surface (26 tools; the 25 cap was the old plan's). Its frames (native viewport first,
  then software views; max 3) become PNGs (`evidence-images.ts`) returned through `StudioGate.callTool`, and the agent
  adds them as one user message on the next step only (`apps/studio/src/evidence.ts`, prepareStep). Kimi K2.7 Code
  accepts images (Workers AI model page: Vision yes).
- Proof: `apps/studio/tests/evidence.test.mjs` runs the real workers-ai-provider against a capturing binding and finds
  the exact PNG as an `image_url` data URL in the request. In production, `lastImageInput` in the admin export records
  each injection (labels, sizes, bytes).
- Limits: native capture is the active camera at most 320x240 (plugin `StudioCapture.luau`); software views are
  approximations. A larger capture and target framing need a plugin release.
